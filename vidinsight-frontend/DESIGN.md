# VidInsight / 灵悉 · 设计规格（DESIGN.md）

> 本文件是 VidInsight 界面的唯一设计真相源，写给 AI 编码代理（Codex / Claude Code / ZCode）消费。
> **任何 UI 任务开始前，先完整读取本文件**；改动与本文件冲突时，以本文件为准或先修订本文件。
> 方法论来源：设计意图 → 结构化规格 → Agent 执行（m3e-canvas 式"先画布后代码"）。

## 0. 产品性格

灵悉把短视频变成可检索、可溯源的洞察。用户是内容运营与市场研究，核心动作是"贴视频 → 得洞察 → 追问"。

性格关键词：**剪辑室（cutting room）× 研究简报**——工作层是视频从业者的深色播放器 chrome，阅读层是干净的简报纸面。视觉词汇从视频题材本身长出来：时间码、轨道、播放头、帧。

三个反目标（出现即算 UI 犯规）：
1. 不出现"蓝色主按钮 + 白色卡片 + 深色左侧栏"的后台默认三件套
2. 不落入 AI 生成签名：暖纸底 + 衬线标题 + 陶土色强调的组合（frontend-design skill 点名的 tell）
3. AI 输出排版不许散：表格、引用、来源标注必须有固定样式

## 1. 双层结构（本设计的核心想法）

- **工作层（剪辑室）**：侧栏与处理中的元素用深色播放器 chrome（#17191E 系），时间码、百分比、工具名一律 mono——机器的声音
- **阅读层（简报）**：报告与回答用冷灰纸面（#F5F6F8 系）白卡，黑主键——人的声音
- 两层只通过**录制红**一个信号色连接：凡"正在发生"的东西（REC 点、转写中的播放头、当前步）都是它

## 2. 设计原则

1. **时间码是装饰也是信息**：百分比、时长、来源标号一律 mono；能显示进度的地方必须显示进度
2. **轨道化表达**：一切"过程"（生成五步、下载、转写）画成轨道上的播放头，不画成转圈
3. **洞察优先**：一屏内能看到"结论 + 来源标注"；装饰永远排在信息后面
4. **失败也是内容**：错误/降级有固定版式（琥珀条/红条 + 下一步动作），不做一闪而过的裸 toast

## 3. 色彩 tokens

| token | 值 | 用途 |
|---|---|---|
| chrome | `#17191E` | 侧栏/播放器 chrome 深底 |
| chrome-2 | `#1F2229` | chrome 内悬停/激活面 |
| studio | `#F5F6F8` | 工作区底色（冷灰，非暖纸） |
| surface | `#FFFFFF` | 卡片/浮层/阅读面 |
| ink | `#1F2328` | 主文字 + **主按钮底（黑主键）** |
| ink-2 | `#5A6068` | 次级文字 |
| ink-3 | `#9AA0A6` | 辅助/占位 |
| rec | `#E5484D` | **录制红：仅"正在发生"语义**（REC 点/播放头/当前步/转写中） |
| teal | `#0E7C66` | 成功/完成态 |
| amber | `#B7791F` | 降级/警告条 |
| danger | `#C0392B` | 失败态 |
| hairline | `#E3E6EA` | 浅区分隔线；chrome 内用 `#2A2E36` |
| tc | mono `#8A9096` | 时间码/百分比/工具名的字色 |

- 禁色：默认蓝系主色、AI 紫渐变、暖纸+陶土组合、荧光绿暗底
- VS Code 式双主题：侧栏永恒深色剪辑室（chrome #17191E），内容区支持冷灰简报（Light）与沉浸剪辑（Dark）双态，全部组件必须用 --vi-* 语义 token，禁止写死 bg-white/border-neutral-200

## 4. 字体与排版

- 中文：system-ui 栈；**mono 层**：JetBrains Mono → Consolas（时间码/百分比/工具名/BV 号）
- 页面标题 20px semibold；区块 16px；正文 15px/1.75；辅助 12px
- 报告页 H1 用 Noto Serif SC（阅读层的"刊头"，仅报告与洞察回答首屏）
- 来源标号 [n]：mono 上标，hover 出来源标题
- 一切数字 `tabular-nums`

## 5. 形状与间距

- 圆角：卡片 12 / 按钮 8 / 输入 8 / 气泡 14（AI 气泡左上 4、用户气泡右上 4）
- 间距 4 的倍数；内容区最大宽 960 居中（阅读型）
- 层级不用阴影：hairline + 底色差；浮层极浅投影 `0 8px 24px rgba(23,25,30,.10)`

## 5b. 组件规范（逐一替换 antd 默认形态）

- **主按钮（黑主键）**：ink 底白字；hover 提亮一档； REC 红只给"停止/进行中"语义
- **五步进度卡（轨道化）**：横向 track——完成步 teal 实心✓、当前步 rec 红实心（外圈脉冲）+ 右侧 mono 百分比、未来步空心灰；步间连线随进度填充 rec→teal；卡头 chrome 深底白字"正在生成 · 转写文字"+ mono 百分比 chip
- **思考过程面板**：mono 11px，左侧 2px rec 轨道线，工具调用 outline pill（含耗时），失败 pill danger 描边
- **侧栏（chrome 层）**：深底白字，激活项左 3px rec 信号条 + chrome-2 面；"新对话"为 chrome-2 描边按钮；底部 mono 版本号
- **失败/降级条**：amber 底 20% + 左 3px amber 边 + 下一步动作；失败卡同构换 danger
- **空状态**：编辑部刊头——大标题 + 一句话定位 + 2×2 建议卡（lucide 线性图标，不用 emoji）
- **视频封面**：16:9，加载淡入；列表中封面优先级高于文字元信息

## 6. 页面规格

| 页面 | 规格 |
|---|---|
| 对话页 | 侧栏 240px paper 底 hairline 分隔；消息区同上；进度卡、思考面板嵌在消息流内 |
| 内容分析 | 双栏：左表单（窄）右实时预览（宽）；预览卡封面大图优先，元信息小字排底部 |
| 分析历史 | 左列表（16:9 缩略 + 标题 + 状态点）右详情；详情 H1 serif；目录锚点固定右侧 |
| 我的收藏 | 与分析历史同构，卡片密度略高 |
| 全局配置 | 弱化边框、用留白分组；每项右侧内联"测试/验证"动作按钮 |

## 6. 动效

- 160–240ms ease-out；不做渐变动画/粒子
- 进度卡步骤推进：圆点一次 scale 弹跳（160ms）
- 流式思考：行尾光标块 1.2s 呼吸；转写百分比数字滚动（tabular-nums）
- 页面切换：仅内容区 fade 120ms，侧栏常驻

## 7. 文案语气

- 状态动词化且带数字："正在转写 62%""已生成，可直接追问"
- 失败永远给下一步动作（"可稍后重试或切换供应商"），不给天书
- 禁止"操作成功"式空话；成功消息说明"现在能干什么"

## 8. 实施顺序（迁移清单）

1. tokens 进 tailwind config + 全局样式层（含 antd primary→vermilion）
2. 五步进度卡 + 按钮体系（出片最快、演示价值最高）
3. 对话页：空状态刊头 + 气泡/思考面板改版
4. 报告详情：serif H1 + 目录锚点 + 来源标注样式
5. 分析历史列表改版
6. 全局配置收口 + 全站回归

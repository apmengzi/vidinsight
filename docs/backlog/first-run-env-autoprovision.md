# Backlog: 首次启动环境自检与自动准备（First-Run Environment Auto-Provisioning）

> 来源：2026-09 实测暴露的真实痛点。优先级：高（直接影响新用户第一次体验）。

## 痛点（真实案例）

1. 本机已有 faster-whisper-small 完整缓存（`D:\projects\.hf-cache\hub\models--Systran--faster-whisper-small`，464MB），便携版仍显示"未下载"，要求重新下载——因为用户自定义了 `HF_HOME`，应用只查自己的 `download_root`，不感知系统里已有的 HF 缓存。
2. 本机 ffmpeg 完整可用（`D:\ffmpeg-...\bin`），部署监控却显示"未安装"——因为只查进程 PATH，不扫常见安装位置（Git Bash / conda / 独立解压目录）。
3. 首次启动后用户要手动配转写引擎、手动触发模型下载，做不到"打开就能用"。

## 需求

**扫描 → 复用 → 补缺 → 后台准备** 四步：

1. **扫描**：首次启动（及部署监控刷新）时，扫描所有依赖的已知位置：
   - Whisper 模型：自身 `models/whisper/` + `HF_HOME`/`HF_HUB_CACHE` 指向的缓存 + 默认 `~/.cache/huggingface` + 常见自定义盘符路径探测（如 `X:\.hf-cache\hub`）
   - FFmpeg：进程 PATH + `FFMPEG_BIN_PATH` + 常见安装目录（`C:\ffmpeg*\bin`、conda `Library\bin`、winget/choco 安装位置）
   - Cookie/配置：旧版数据目录迁移探测
2. **复用**：命中即登记（复制或以符号链接/缓存目录注入方式接入），绝不重复下载；部署监控如实显示来源（`已复用本机缓存` / `已下载` / `缺失`）。
3. **补缺**：确认真缺失的，才进入下载队列；下载在**后台**进行，不阻塞 UI，进度可见。
4. **后台准备**：首次启动即后台准备默认基线环境（fast-whisper 默认模型 + ffmpeg 检测），完成后通知"所有基础功能就绪"；LLM Key 之外做到**零手工配置**。

## 验收标准

- [ ] 全新 Windows 机器：双击安装/解压 → 打开 → 除填 LLM Key 外，转写/生成/问答全流程无手工环境配置
- [ ] 已有 HF 缓存的机器：检测到即复用，零重复下载（用流量/时长断言）
- [ ] 部署监控每个组件显示真实来源与状态
- [ ] 所有"检测/复用"行为有日志（[EnvScan] 前缀），可审计

## 关联

- 顺带修：转写引擎的 API Key 应在转写配置页就近填写（Groq key 目前要去 LLM 供应商页填，反直觉）
- 顺带修：部署监控 CUDA 检测应给出可执行指引（缺哪个 DLL、去哪装），而不是笼统"不可用"

## 关联需求：浏览器 Cookie 一键获取（2026-09-07 用户提出）

手动复制浏览器 Cookie 的配置成本过高（F12 → 找请求头 → 复制长字符串）。
候选方案：
1. 浏览器插件一键同步（插件端已有该能力，桌面端可引导安装插件）
2. 桌面端本机读取浏览器 Cookie 库（Chrome 系为 DPAPI 加密，需 browser_cookie3 类方案；注意杀软误报与隐私提示）
3. 应用内嵌 B站二维码登录，登录态直接写入 cookie manager（体验最好，工作量中等）
验收：用户零 F12 操作完成 Cookie 配置。

## 关联需求：对话任务卡片按会话隔离（2026-09-07 用户反馈）

进度/完成卡片存于全局 taskStore，未按 conversationId 作用域化：
- 切到新对话，原对话的完成卡片仍显示
- 路由切换（去分析历史再回来）组件重挂载，卡片全部消失
修复方向：卡片状态按会话持久化（入 conversationStore 或 IndexedDB），切换会话时按 id 过滤渲染。

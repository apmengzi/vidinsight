## 零、先说明三件会直接影响评审的事（建议开场先跟老师对齐）

### 1. 我们是纯软件产品，硬件维度需做等价翻译

课程给的 B 维度（空间适配 / 温湿度 / 噪音）是**硬件产品口径**。VidInsight 是 Windows 桌面软件（Tauri 2 + 本地 Python 后端 **sidecar**，无云端依赖），没有结构件、不发热、不发声。若按字面造测试项会得到"把软件放桌上量尺寸"这种无意义项。

**我们的等价翻译**（保持课程意图——验证"脱离实验室环境后在真实场景的表现"）：

| 课程原维度 | 硬件产品的含义 | 本产品的等价项 | 保留的课程意图 |
|---|---|---|---|
| 空间适配 | 台面能否容纳产品及配套物料 | **安装与运行占位**：磁盘占用、内存常驻、端口占用（8483）是否与其它软件冲突 | "真实环境放得下、不打架" |
| 温湿度边界 | 环境温湿度范围 | **运行环境边界**：Windows 版本（10/11）、无 FFmpeg / 无 Python 的裸机、中文用户名路径、非管理员权限 | "不同环境下都能跑" |
| 噪音参数 | 使用时的噪音水平 | **资源占用噪声**：转写时 CPU 占用、风扇/卡顿感知、后台静默（不弹窗、不抢占焦点） | "使用时不打扰用户" |

**这一条建议主动向老师说明**，并请老师确认翻译口径是否接受——这是本清单最需要协商的一点。

### 2. "双机一致性"对我们 = 两台不同配置的 Windows 机器跑同一矩阵

课程口径的双机是"1号机/2号机硬件结构公差"。软件没有公差，等价为：
- **机器 A**：开发机（已装 Python/FFmpeg/Node，环境"脏"）
- **机器 B**：**全新裸机**（无 Python、无 FFmpeg、无 Node，模拟真实用户）

重点验证：**安装包是否自带全部运行环境**（这是软件产品"工程化通用性"的真问题，对应课程"规避单台设备专属适配问题"）。当前 MSI 产物为 2026-10-02 构建（566 MB），**尚未包含 10-04 之后的修复**，需重打包后才算有效（见第四节前置条件）。

### 3. EVT 阶段不新增功能 —— 本清单只做验证

按课程要求，EVT 阶段**不新增功能**，只验证 POC 已定的核心功能。以下清单全部是**验证项**，不含任何新功能开发。

## 一、测试项清单

分级口径（课程四级）：**致命**=不解决无法交付；**严重**=影响核心体验，须本阶段解决或有明确规避；**一般**=次要功能有替代方案可延后；**轻微**=不影响核心功能，记录备案。
优先级：**P0=必须做**（致命/严重）· **P1=建议做**（一般）· **P2=记录备案**（轻微）。

## 四、与老师的三个协商问题（建议主动提出）

1. **硬件维度翻译是否接受？** 我们是纯软件，"空间/温湿度/噪音"已等价翻译为"安装占位/运行环境边界/资源占用噪声"。请老师确认口径，或指点更合适的等价方式。

# 用户测试资料 · 目录说明

> 项目：灵悉 VidInsight（赛博大胃袋）· 阶段：EVT Beta 样机
> 提交形式：本文件夹打包为压缩包上传（一组一份）

## 目录结构（对应作业要求）

```
用户测试/
├── 01_用户使用过程视频/          ← 作业要求 1：用户使用过程的视频（可选）
├── 02_测试后反馈与访谈/          ← 作业要求 2：测试后用户反馈与访谈
│   └── 访谈记录.md                    （3 名用户的访谈要点整理）
└── 03_用户测试报告/              ← 作业要求 3：用户测试报告
    ├── 用户测试报告.md                 （含痛点与分析、洞察、未来迭代方案）
    └── EVT_Beta修改项_证据链.md         （课堂任务：证据→问题→洞察→修改）
```

## 各文件说明

| 文件 | 对应作业项 | 内容 |
|---|---|---|
| `01_用户使用过程视频/` | 要求 1（可选） | 3 名用户操作过程的屏幕录制（含出声思维），每段约 15 分钟 |
| `02_测试后反馈与访谈/访谈记录.md` | 要求 2 | 3 名用户的访谈问答整理，含关键原话引用 |
| `03_用户测试报告/用户测试报告.md` | 要求 3 | 测试目标、对象、方法、**完整试用场景与过程**、痛点分析、洞察、迭代方案 |
| `03_用户测试报告/EVT_Beta修改项_证据链.md` | 课堂任务 | 按"测试证据 → 用户问题 → 洞察 → EVT Beta 修改"四列组织，分 Must/Should/Could Fix |

## 本轮测试结论（一句话）

**核心流程可独立完成，但"用户无法判断系统是在工作还是卡死"是最影响信任的问题**——已定为 Must Fix，将在 EVT Beta 样机中落地。

## 测试基本信息

- 测试日期：2026-10-12
- 测试版本：VidInsight 2.5.0（桌面端安装版）
- 测试人数：3 人（内容创作者方向，符合目标用户画像）
- 测试形式：1 对 1，全程无口头指导，操作后 15 分钟半结构化访谈

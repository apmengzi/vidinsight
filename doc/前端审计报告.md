## 结论先行

VidInsight 的核心产品愿景（剪辑室深色 chrome 品牌壳 × 浅色纸面研究简报）立意清晰，且在 `ChatPage`、`AppLayout`、`BoardPage` 等近期重构模块中已展现出色的工具质感；但在全站工程落地中，**新旧设计系统严重混杂**：
1. **系统性撕裂**：老页面的 shadcn/antd 默认蓝系（`#3c77fb` / `bg-blue-600`）与新设计系统的「黑主键 + 极简冷灰 + 单一 REC 红」严重对撞，AI 玩具感与通用后台感在多处死灰复燃；
2. **加载体验滞后**：除 `ChatPage` 具备部分流式呼吸感外，全站多处仍在使用老旧的旋转 Loader、整块生硬切屏、无骨架屏扫光与同色模糊占位；
3. **视觉对齐失准与暗色硬伤**：全局 CSS 存在暗色模式边框反向致盲硬伤，全局配置各子页未接入双主题 tokens，仍硬编码纯白底与灰色分割线。

通过**收拢色彩 Token、补齐长列表渐进模糊与骨架屏、重构老旧表单/设置页面**，可在较小工作量下彻底消除「AI后台模板味」，真正呈现「昂贵、克制、专业」的剪辑室级生产力工具质感。

## 一、三项已知硬伤核实

### 硬伤 A：shadcn 默认蓝 `--primary: #3c77fb` 残留
- **证据文件及行号**：
  - `src/index.css:39`：`--primary: #3c77fb;`
  - `src/index.css:74`：`--primary: #3c77fb;`
  - `src/index.css:51`：`--ring: #096dd9;`
- **问题分析**：`DESIGN.md` 第 3 节明确将「默认蓝系主色」列为第一禁色，要求主操作采用黑主键（`ink: #1F2328`）。然而 shadcn 根变量保留了经典默认高亮蓝，导致下游使用 `bg-primary`、`text-primary` 的组件（如 `NoteForm.tsx:433`、`StepBar.tsx:29`、`MarkdownViewer.tsx:123` 标题等）全盘泛蓝，形成了浓烈的「AI Demo 默认模板味」。

### 硬伤 B：`.dark` 块中边框变量反向写错为浅亮色
- **证据文件及行号**：
  - `src/index.css:84`：`.dark { --border: #e6f7ff; }`
- **问题分析**：`#e6f7ff` 是高亮且近乎白色的极浅粉蓝（浅色模式下的极淡遮罩色）。将其作为 `.dark` 暗色模式下的 `--border`，导致在暗色主题下所有采用 shadcn 的卡片与组件边框变成刺眼炫目的浅白高亮线，严重破坏暗调工作区沉浸感。暗色边框应统一使用 `--vi-hairline`（`#2A2E36`）或 `oklch(1 0 0 / 10%)`。

### 硬伤 C：`DESIGN.md` 文档严重滞后于主题实现
- **证据文件及行号**：
  - `DESIGN.md:50`：`深色模式暂不做：双层结构已承担明暗对比`
  - `src/layouts/AppLayout.tsx:156-165`：已实现 `Sun` / `Moon` 主题切换按钮，文案为「浅色工作面 / 深色剪辑室」
  - `src/index.css:171-194`：已实现完整的 `:root` 与 `.dark` 的 `--vi-*` 双主题 tokens
- **问题分析**：代码已迈向 VS Code 式双主题架构（侧栏 Chrome 常暗，右侧编辑区支持 Light/Dark 切换），但核心设计文档仍声明「深色模式暂不做」，导致后来代码缺乏统一的深色模式适配指引（部分组件手写 `bg-white`，部分手写 `bg-[var(--vi-bg)]`）。
- **更新要点**：
  1. 修正 `DESIGN.md` 第 3 节，正式确立「侧栏永恒深色剪辑室（Chrome），内容区支持冷灰简报（Light Studio）与沉浸剪辑（Dark Studio）双态」；
  2. 规定所有组件必须使用语义化 `--vi-*` tokens，禁止直接写死 `bg-white` 或 `border-neutral-200`。

## 三、与设计知识库的差距分析

对比用户收藏提炼的《设计知识库-来自收藏.md》，当前系统在高级质感表现上存在 5 大系统性差距：

| 知识库维度 | 知识库高级感标准 | VidInsight 现状缺陷 | 质感差距评级 |
|---|---|---|---|
| **1. 克制（总纲）** | 大留白 + 极少颜色（黑白灰主体，单一点缀色）；层级靠字号字重而非色彩数量；不加多余装饰 | 全局残留 `#3c77fb` 默认蓝，彩色 Badge（粉红/青绿）、彩色 Monitor 图标堆叠，引导页蓝粉渐变，颜色多达 7 种以上，割裂用户注意力 | 🔴 严重违背 |
| **2. 加载体验四维** | **骨架屏扫光**（如退潮浮现）、**逐块出场**（fade-in-up）、**同色模糊占位**（对焦感）、**提前预载** | 普遍使用转圈小菊花（`Loader2 animate-spin`）或纯白屏；图片未加载时出现灰色色块硬切；对话回复仍有卡顿后突然成块渲染的现象 | 🔴 显著滞后 |
| **3. 渐进模糊 (Progressive Blur)** | 列表/卡片流底部不用生硬横线，采用 0→16px 渐进羽化模糊，内容向底部自然隐去 | `ChatPage`、`HistoryPage`、`BoardPage` 的滚动容器底端均被固定纯白输入栏或边框「刀切式」硬截断，缺乏现代高端应用的情境流动感 | 🟡 尚未应用 |
| **4. 视觉对齐 (Optical Alignment)** | 图标按视觉重心微调（不按几何边界），左右边距统一，字号层级严谨符合 4/8 栅格 | 侧栏图标与文字距离不均；按钮内小图标偏沉未上提 1px；部分标题使用 `text-3xl` 部分使用 `text-2xl`，字阶缺乏系统步长 | 🟡 局部欠缺 |
| **5. AI 味道消除** | 消除等距三卡片、蓝色默认键、居中大标题、科技感紫粉渐变 | `MarkdownViewer` 默认高亮蓝标题、`Onboarding` 蓝粉渐变、`StepBar` 的 1-2-3 圆圈、`Monitor` 的彩色指标卡均属典型 AI 模板味道 | 🔴 明显暴露 |

## 四、改进方案与实施路径

改进方案按 **视觉收益 / 工作量** 严格排序，前三项列为 **Top3 优先项**。

```
                    高视觉收益
                        ▲
                        │  ★ Top1: 根除默认蓝与暗色硬伤
                        │  ★ Top2: Markdown阅读层与步骤条重构
                        │  ★ Top3: 滚动流渐进模糊与骨架屏
                        │
                        │      4. 设置页与监控卡去后台化
                        │      5. 引导页去粉蓝玩具感
                        │      6. 图标视觉重心与间距精修
                        ┼────────────────────────► 低工作量
```

### ★ Top 1：收拢全局 Token，彻底拔除默认蓝与修复暗色致盲（高收益 / 极低工作量）
- **核心动作**：
  1. 修改 `src/index.css`，将 `--primary` 从 `#3c77fb` 改为黑主键 `#1F2328`（dark 模式下为 `#E8EAED`），`--primary-foreground` 相应反转；
  2. 修复 `.dark` 块内 `--border: #e6f7ff` 硬伤，替换为 `var(--vi-hairline)`（`#2A2E36`）；
  3. 全局搜索清理孤立的 `bg-blue-600`、`text-blue-600`，切换至语义化黑主键 `bg-ink text-white hover:bg-[#2A2F36]`；
  4. 同步更新 `DESIGN.md` 文档，正式承认并规范 VS Code 式双主题架构。
- **涉及文件**：
  - `src/index.css`

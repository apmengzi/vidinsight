## 一、总纲：高级感 = 克制，不是加东西

**来源：《高级 UI 的克制感》（设计机构 Sacro 作品拆解）**

1. **大留白 + 极少颜色**：黑白灰做主体，只用一个点缀色（绿/橙/紫/红任选其一）标重点。
   用户第一眼不被颜色打散注意力，立刻知道哪里是数据、哪里是按钮、哪里最重要。
2. **层级靠字号/字重/间距，不靠颜色数量**：「高级的界面不是把所有东西都做大，
   而是知道什么该安静、什么该被看见」。扫一眼先看到趋势 → 再看细节 → 最后读说明。
3. **真实场景感**：界面放进设备模型/真实环境呈现（金融 App 放暗光环境 = 专业与安全感；
   电商把产品放大、留足呼吸感，售卖感更强）。
4. **交互感**：界面要「真的可以点、可以拖、可以操作」，不是一张摆拍页面——
   AI 工具的问答模块、筛选器的滑动，都在强调这一点。
5. **结论**：把每个元素放到**刚刚好**的位置。信息整理好、视觉克制住、交互细节精致，
   设计自然显得专业可信——「而且很贵」。

## 二、加载体验四维（最容易露馅的地方）

**来源：《4句提示词，让App加载也很高级✨》**

加载阶段决定产品的专业感。四个维度逐一检查：

| 维度 | 常见错误 | 高级做法（含比喻） |
|---|---|---|
| 等待时看什么 | 白屏转圈 | **骨架屏扫光**：先摆好内容的影子，光扫过去，像退潮一块块露出来 |
| 内容出场方式 | 一下子全砸下来 | **逐块出场**：内容一块块浮现，不是整屏蹦出 |
| 版面稳定 | 加载前后跳动 | **同色模糊占位**：图片先铺同色模糊层，到位后像相机对焦慢慢变清楚 |
| 加载时机 | 滑到底才卡一下加载 | **提前预载**：没到底就开始加载，新内容像传送带一件件接上 |

**AI 流式回复的专门做法**（VidInsight 流式问答直接适用）：气泡马上出来 + 小点在呼吸
（表示「它在响」）+ 回复一段段浮出，而不是干等几秒后整段砸下来。

## 三、渐进模糊（progressive blur）

**来源：《VibeCoding做UI必会的概念：渐进模糊》**

- 手法：列表底部**不用分割线**，加一层渐进模糊——从悬浮按钮上方约 120pt 开始，
  模糊半径 0 → 16 渐变，悬浮按钮本身保持清晰。
- 效果：内容在模糊层下继续滚动隐去，现代 iOS / 高级 App 的标志性收尾手法。
- VidInsight 适用点：长列表页（历史页/收藏页）底部的悬浮操作区。

## 四、视觉对齐（optical alignment）

**来源：《VibeCoding做UI必会的概念：视觉对齐》——「AI 做的页面总差一口气，多半差在这里」**

- 左右边距统一；该居中的居中；同一列文字左边对齐。
- **图标按视觉重心微调，不按几何边界**：播放三角往右挪一点（重心偏左），
  星星和下载图标往上提一点（重心偏下）。
- 这是 AI 生成界面的系统性弱点：几何对齐了但视觉没对齐，页面显得「廉价的不整齐」。

## 五、动效词汇表（先能命名，才能精确描述）

**来源：《想要 Vibe Coding？先学会动效描述！第2期》**

| 效果 | 名称 |
|---|---|
| hover 时石头向周围散开 | 距离驱动的粒子散逸 |
| 鼠标移动使物体形变 | 指针驱动的网格变形 |
| 下滑时 3D 物体停在视口不动 | 滚动固定（scroll pinning） |
| hover 图片直接动起来 | 全屏触发视频预览 |
| 用力滑动图片变窄、停手回弹 | 滚动速度驱动的形变 |
| hover 的格子变宽、邻格变窄 | hover 情势扩展布局 |

> 适用度提示：以上多为展示型网站的戏剧化动效。VidInsight 是**工具类应用**，
> 按 DESIGN.md「160-240ms ease-out，不做渐变动画」的纪律，只取「命名→精确描述」
> 方法论与个别克制变体（如 hover 扩展布局可用于收藏卡片），不照搬大动效。

## 六、元认知：为什么 AI 做的界面总像后台

**来源：《AI做的界面为什么总像后台？》（m3e-canvas 拆解）**

- 蓝色按钮 + 白色卡片 + 后台管理布局 = 模型在**需求模糊时的默认猜测**，
  不是模型审美差——「你说的简洁、高级、有科技感，在模型眼里根本没有唯一答案」。
- 自然语言擅长描述**目的**，不擅长表达**空间关系与交互状态**
  （隔多远？放大字号还是改颜色？滑动弹入还是直接切换？）。
- 解法：先把设计意图**结构化/可视化**确定下来，再交给模型执行
  （VidInsight 的 DESIGN.md 正是这层「稳定的机器上下文」）。
- **对阶段 C/D 的直接要求**：实施提示词必须落到具体文件、具体 token、具体数值，
  禁止「提升质感」「更有设计感」这类不可执行描述。

## 八、对 VidInsight 的适用度分级（供阶段 C 对照）

结合 DESIGN.md「剪辑室 chrome 工作层 × 简报阅读层、录制红语义、克制动效」的既有定位：

1. **直接适用（应进审计对照清单）**：
   - 克制三原则：大留白/黑白灰+单点缀色/层级靠字重字号 —— 对照各页面是否颜色过多、层级不清
   - 加载四维：骨架屏扫光、逐块出场、同色模糊占位、提前预载 —— 对照历史页/收藏页/图片加载
   - 流式回复的呼吸点+逐段浮现 —— 对照 ChatPage 流式问答
   - 渐进模糊收尾 —— 对照长列表底部悬浮操作区
   - 视觉对齐（图标重心微调）—— 对照侧栏图标、按钮图标
2. **方法论适用（不照搬成品）**：动效命名表、结构化设计意图（六）
3. **不适用**：WebGL 3D、展示型戏剧动效、视频制作工作流

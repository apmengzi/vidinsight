# 可写进简历的量化结果（秋招冲刺 T0-T2 产出）

> 全部数字为 2026-09-12 实测，可复现（命令见各节）。面试被追问时每条都有实验细节可讲。

## 1. 检索评测体系（T1）——简历 RAG 项目核心数字

- 构建 **40 条人工标注评测集**（6 篇去重真实视频笔记，228~481 chunks，region 级相关性标注，跨 chunk 粒度可比），实现 4 策略自动化评测脚本（`backend/tests/eval_retrieval.py`）。
- **定位并修复致命缺陷**：Chroma 默认嵌入（英文 MiniLM）对中文语料 Recall@5 仅 **0.008**（等于不可用）——这正是线上关闭向量检索的根因；换 `bge-small-zh-v1.5` 后恢复至 **0.346**。
- **混合检索 + Reranker 精排**（生产 250 字分块）：MRR **0.582 → 0.693（+19%）**，NDCG@10 **0.448 → 0.494**；精排主要提升排序质量而非召回量。
- **chunk 粒度实证**（回答「chunk 怎么设计」）：125/250/500 字下 BM25 Recall@5 = **0.395 / 0.408 / 0.558**——检索侧大粒度占优，但需权衡生成侧上下文密度，不能只看检索指标。
- **负结果与取舍**：BGE-Reranker CPU 推理 **10~18s/查询**（fp32），生产环境保持 `RERANKER_ENABLED=0` 是数据支撑的正确决策；GPU 部署可开启。

复现：`cd backend && python tests/eval_retrieval.py --chunk-sizes 125 250 500`

## 2. 长任务取消机制（T2）——「Agent 任务耗时很长怎么停止？我实现过」

- 设计**协作式取消**：API（`POST /tasks/{id}/cancel`）→ 进程内取消注册表（线程安全）→ 阶段边界 / LLM 轮次边界检查 → 抛 `TaskCancelled` → CANCELLED 终态。
- 关键设计点（面试追问）：**正在飞行中的单次 LLM/网络调用不可中断**，取消只能在轮次边界生效——延迟上界=单轮调用耗时；该边界是主动设计而非缺陷。
- 终态保护：取消后，即使后续阶段抛出其他异常（实测 402 余额不足），也不会覆盖 CANCELLED 状态。
- **断点续跑**：总结阶段按 chunk 落盘 checkpoint，取消/失败后重试已完成 chunk 不重算。
- 验证：单测 5 例新增（注册表语义 + 状态写入），回归 **24/24 通过**；真实 B 站任务下载中取消端到端通过（PENDING→DOWNLOADING→**CANCELLED**，状态稳定）。

## 3. 边界自证与 Harness 分层（T0/T5）——面试保命与深度

- `doc/UPSTREAM_VS_OURS.md`：基于 git 历史的上游（VidInsight v2.4.0）vs 自研边界清单，**简历与面试只主张自研 Agent 层**（ReAct 循环、混合检索知识库、BM25/Reranker、安全护栏）。
- `doc/HARNESS.md`：把已有机制重组为六层 harness 叙述（input/context/tool/runtime/state/safety），对应「状态怎么管、断了怎么恢复、工具为什么不会乱调」。

## 4. 其他已验证工程数字（此前迭代，均可讲）

- faster-whisper small int8 CPU：2 分 43 秒视频 59 秒完成转写（RTX 显存不足场景的落地取舍）。
- garak 自研探针扫描：12 探针（注入+越狱），92% 防御率；已知缺口：多语言绕过。
- 修复 Windows 桌面端 0xC0000017（桌面堆耗尽）：根因是健康监测每 5s 拉起 ffmpeg 子进程，加 TTL 缓存后归零。
- B 站 412 反爬三层根因修复（僵尸进程干扰诊断 / Cookie 单例固化 / 下载工具过期），修复后同链路 412 归零。
